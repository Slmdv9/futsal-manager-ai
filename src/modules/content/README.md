# Content module

Owns Category reference data, Exercise, Programming, the bundled content package, and the read layer that powers browsing. Board Data is a shared kernel in `src/shared/domain/board-data` because content, board, and AI all exchange it. The durable contract is `docs/content-model.md`.

## Layers

- `domain` — active. Seven frozen RFEF `Category` brackets, `Exercise` with its `collection` (`exercise-collection.ts`) and optional `references`, `Programming`, the shared `SESSION_PARTS`/`SessionPart` vocabulary in `session-part.ts`, `ContentProvenance` plus the licence policy helpers in `provenance.ts` (`PUBLISHABLE_LICENSE_STATUSES`, `isPublishableProvenance`, `requiresAttribution`, `isLicenseStatusAllowedForKind`), the strict `content-package.ts` contract (`CONTENT_PACKAGE_VERSION`, `parseContentPackage`, `safeParseContentPackage`, `ContentValidationError`), and the `ContentRepository` port in `domain/ports`.
- `application` — active. Publishable-only use cases: `listCategories`, `listExercises` (both collections), `listLibraryExercises`, `listWeeklyHighlights`, `getExercise`, `getProgramming`.
- `infrastructure` — active. `content/content-package.json` plus `bundled-content-repository.ts` (`createBundledContentRepository`), which imports the JSON as `unknown`, parses it once, and indexes it. The bundled seed holds 50 library exercises, 21 weekly highlights and seven Programming records (one per RFEF category) at `contentVersion` `1.2.0`: six categories carry seven library exercises split 2/3/2 by `sessionPart`, Infantil U14 keeps its nine split 2/5/2, each category has three weekly highlights (one per part), and `infantil-u14-base` stays at record version `1.1.0`.
- `presentation` — active. `ExploreScreen({ repository })` composes the general Explorar screen: a compact app bar and `ExploreHero` (real counts from `listExercises`/`listCategories`, so `71 Ejercicios`), `CategoryFilterBar` (seven RFEF `FilterChip`s under `CATEGORÍA / RANGO DE EDAD`), `MethodologyOverviewCard` (a glance card derived from the selected `Programming` record), `WeeklyExercises` (the category's three weekly highlights in warm-up → main → cool-down order, subtitle `Una selección fuera de la biblioteca`, counter `N ejercicios`), `ExerciseLibraryList`, which renders the three Spanish session-part headings with counts, and `AiSessionEntryCard` as the last product card (a `Link` to the existing `/asistente` tab with no `ai` module import), immediately above the retained `Ver sistema de diseño` technical footer. The single `<AiSessionEntryCard />` element sits outside the selected/unselected branch, so it follows the library when a category is selected and the `Elige una categoría` prompt otherwise. Every library card carries exactly one `Abrir en Pizarra` action: a `Link asChild` from `buildBoardHref(exercise.id)` wrapping a full-width secondary `AppButton` with exercise-specific accessibility copy and a local 48 dp `minHeight`; weekly cards and the prompt expose no action. Session-only selection lives in `state/category-selection.ts` (pure reducer) and `state/category-selection-provider.tsx` (`CategorySelectionProvider`, `useCategorySelection`), mounted once in `src/app/_layout.tsx`; `view-models/category-browse-model.ts` builds the library-only model through `listLibraryExercises`/`getProgramming`, groups it with `groupExercisesBySessionPart`, and owns the Spanish formatters, `view-models/explore-general-model.ts` owns the hero stats, the weekly block from `listWeeklyHighlights`, the methodology mapping and `formatWeeklySelection(count)`, and `view-models/board-routing.ts` owns `buildBoardHref` plus `buildBoardExerciseTarget`, the pure `Exercise` → `{ id, title, summary, boardData }` mapping that lets the route target Pizarra without `content` importing `board`. `ProgrammingSummaryCard` was retired because the methodology card owns its fields. `components/exercise-detail-link.tsx` wraps each library and weekly card's title, summary and meta in one accessible `Link asChild` + `Pressable` with a visible detail label and a 44 dp target that opens `/ejercicios/[exerciseId]`; it is a sibling of the library's board action, and weekly cards stay board-free. `screens/exercise-detail-screen.tsx` renders the header card, the seven-row `Ficha del ejercicio`, `Restricciones`, `Paso a paso`, `Consignas para el entrenador`, `Inspirado en` and `Atribución` from `view-models/exercise-detail-model.ts`, which owns all detail copy, sorts phases by `order`, emits text-only phase fields, defaults `references` to `[]`, reads `provenance.attribution`, and never mutates the exercise; `view-models/exercise-detail-routing.ts` owns the typed `/ejercicios/[exerciseId]` href. The screen draws no pitch, SVG or playback — the animated board belongs to `tactics-board-renderer`.

## Public API

`src/modules/content/index.ts`. Other modules and routes must not import this module's internals directly. It exports the categories, package parser and error, entities, `EXERCISE_COLLECTIONS`/`ExerciseCollection`/`ExerciseReference`, `SESSION_PARTS`/`SessionPart`, port, use cases including `listLibraryExercises` and `listWeeklyHighlights`, the bundled repository factory, `ExploreScreen`, `ExerciseDetailScreen`, the session selection state and provider (`INITIAL_CATEGORY_SELECTION`, `selectCategory`, `CategorySelectionProvider`, `useCategorySelection`), the browse view model plus formatters (`buildCategoryBrowseModel`, `groupExercisesBySessionPart`, `formatCategoryLabel`, `formatExerciseMeta`, `formatSessionDuration`, `formatExerciseCount`, `formatSessionPartLabel`, `SessionPartGroup`), the board routing helpers (`buildBoardHref`, `buildBoardExerciseTarget`, `BoardExerciseTargetData`), the detail model and routing helpers (`buildExerciseDetailModel`, `buildExerciseDetailHref`, `ExerciseDetailModel`, `ExerciseDetailPhase`, `ExerciseDetailRow`, `ExerciseDetailHref`), and the general explore model (`buildExploreGeneralModel`, `buildExploreStats`, `buildWeeklyExercises`, `buildMethodologyOverview`, `formatWeeklySelection`, `WEEKLY_EXERCISES_PER_PART`, `METHODOLOGY_KEY_CONCEPTS_LIMIT`, `ExploreGeneralModel`, `ExploreStats`, `WeeklyExercise`, `MethodologyOverview`). `ExerciseDetailLink` stays internal to `content/presentation`.

Browse flow: route → `createBundledContentRepository` → `ExploreScreen({ repository })` → session category selection → browse/weekly view models → read use cases → `ContentRepository` → bundled adapter → shared `parseBoardData`.

Board flow: library card → `buildBoardHref(exercise.id)` → `/pizarra?exerciseId=<id>` → `app/(tabs)/pizarra.tsx` → `getExercise` → `buildBoardExerciseTarget` → `board` `BoardScreen exercise={…}`. `content` passes a board-safe target and never imports `board`; unknown or unpublishable ids resolve to `null`.

Detail flow: library or weekly card → `ExerciseDetailLink` → `buildExerciseDetailHref(exercise.id)` → `/ejercicios/[exerciseId]` → `app/ejercicios/[exerciseId].tsx` → `getExercise` → `ExerciseDetailScreen exercise={…}` → `buildExerciseDetailModel`. The route is the only place that resolves the param; the screen performs no lookup and no fetch. Unknown, empty or unpublishable ids pass `null` and render `Ejercicio no encontrado`.

## Rules

- Categories exist only as domain reference data; the package references ids and parsing rejects unknown ones.
- Every exercise declares a required `sessionPart` (`warm-up`, `main`, or `cool-down`); the parser never defaults it, and grouping preserves package order inside the fixed session-part order.
- Every exercise declares a required `collection` (`library` or `weekly`); `listExercises` spans both, while `listLibraryExercises` and `listWeeklyHighlights` narrow the same publishable set. The browse model reads the library collection only.
- `references` is an optional inspiration citation (`{ label, url }`, max 3, absolute http(s)), not provenance and not a licence. The parser rejects non-http(s) URLs; the weekly seed carries exactly one citation per record.
- Every exercise `boardData` is validated with `parseBoardData`; issues surface under `exercises.<i>.boardData.`.
- Licensing is a gate, not a note: parsing rejects published content unless its `licenseStatus` is `owned` or `permitted`, rejects `kind`/`licenseStatus` contradictions, and requires `attribution` for published `permitted`/`cmd-mora` records. Policy and source register: `docs/content-licensing.md`.
- Visibility means `published` **and** publishable: `listExercises`, `listLibraryExercises`, `listWeeklyHighlights`, `getExercise`, and `getProgramming` use `isPublishableExercise` / `isPublishableProgramming`, so an unlicensed record never leaks from a non-bundled repository. `isPublishedExercise` / `isPublishedProgramming` are status-only helpers, never a visibility rule.
- Programming returns one publishable record per category or `null`.
- A two-category exercise appears once under each category and never twice in one result.

## Tests

Mirror the source path under `tests/modules/content/`. `node:test` cannot load React Native, so node tests import layers directly; the presentation suites cover the pure selection reducer, the browse view model, the general explore view model, the board routing helpers, the exercise detail model and href, the app composition wiring (Explorar, Pizarra and exercise detail), plus source-structure guards for the screens and components (`tests/modules/content/presentation/screens/explore-general-screen.test.ts`, `screens/exercise-detail-screen.test.ts`, `components/exercise-library-list.test.ts`, `components/exercise-detail-link.test.ts`, `components/weekly-exercises.test.ts`, `presentation/pizarra-wiring.test.ts`, `presentation/exercise-detail-wiring.test.ts`), while `tests/modules/content/index.test.ts` checks the public API surface. Seed suites: `infrastructure/seed-weekly-highlights.test.ts` owns the 21-record weekly contract (metadata, boards, references, versions), and the existing seed suites keep the 50 library records and seven Programming plans pinned. The device smoke covers the rendered routes.
